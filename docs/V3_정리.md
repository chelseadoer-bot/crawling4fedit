> 작성 목적: **지금까지 만든 것**과 **v3에서 요구하는 것**을 한눈에 맞추고, **가장 빠른 진행 순서** 제시

## 1. 한 줄 요약

| 구분 | v3 명세 | 현재 프로젝트 |
|------|---------|---------------|
| 목적 | 플랫폼/브랜드 **스케줄 크롤링 + 증분 + 26컬럼 CSV** | **UI에서 브랜드 추가 → 크롤링 → 4컬럼 CSV** |
| 출력 | `output/platform/`, `output/brand/{카테고리}/` | `data/output/{brand_id}/{brand_id}_products.csv` |
| 스키마 | 26컬럼 (platform, likes, details …) | UI용 4컬럼 (이미지, 상품명, 가격, 컬러) + 내부 15컬럼 |
| 스케줄 | 요일별 09:00 KST 자동 실행 | 수동 (UI 버튼 / API / 스크립트) |
| 증분 | checkpoint JSON + 신상품순 | ❌ 미구현 (매번 전량 수집) |

**결론:** 크롤러·UI **뼈대는 갖춤**. v3 완전 준수하려면 **CSV 스키마 확장 + 폴더/파일명 규칙 + 증분 + 스케줄러** 4가지만 추가하면 됨.

```
0604_크롤링_ver1/
├── config/brands.json          # 등록 브랜드 (zara, uniqlo, 29cm, dior)

│   │   └── browser_utils.py      # UA, 팝업 닫기
│   ├── core/csv_schema.py        # SIMPLE(4) + STANDARD(15) 컬럼
│   └── services/crawler_service.py
├── data/output/
│   ├── zara/zara_products.csv       # 247
│   ├── uniqlo/uniqlo_products.csv   # 195
│   └── 29cm/29cm_products.csv       # 24,904
├── frontend/                   # 다크 UI, 브랜드 추가/크롤링/다운로드
└── scripts/run_new_brands.py   # 브랜드 일괄 추가·크롤링
```

### 실행 방법 (지금 쓰는 방법)

```powershell
# 백엔드
cd backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# 프론트
cd frontend
npm run dev
# → http://localhost:5173
```

UI: 좌측 `+`로 URL 넣어 브랜드 추가 → 선택 → **크롤링 & 저장**

## 4. v3 스키마 vs 현재 CSV

### v3 (26컬럼, 고정 순서)

`platform`, `is_ranking`, `rank`, `brand`, `brand_likes`, `main_category`, `category`, `gender`, `product_detail_url`, `product_name`, `color`, `color_chip`, `thumbnail`, `likes`, `views`, `details`, `material`, `current_price`, `regular_price`, `discount_rate`, `rating`, `reviews`, `sales`, `manufacture_date`, `crawled_at`, `reorder`

- `crawled_at`: **YYMMDD** (예: `260604`)
- 가격: **숫자만** (₩·쉼표 제거)
- 파일명: `{brand_or_site}_{YYYYMMDD}.csv`
- 저장: `output/platform/` 또는 `output/brand/{spa_domestic|luxury|…}/`

### 현재 (UI 출력 4컬럼)

`이미지`, `상품명`, `가격`, `컬러` — 가격은 `₩ 59,900` 형식

### 매핑 (빠른 변환 기준)

| v3 | 현재 STANDARD | 비고 |
|----|---------------|------|
| platform | — | 플랫폼 크롤 시 `무신사`/`29cm`/`wconcept`, 브랜드 직접 시 `""` |
| brand | brand | 29CM은 입점 브랜드명을 itemInfo.brandName에 이미 수집 |
| product_detail_url | product_url | |
| thumbnail | image_url | |
| current_price | price_sale or price_original | v3는 숫자만 |
| main_category / category | category_large / category_small | |
| crawled_at | crawled_at | 형식만 YYMMDD로 변경 필요 |
| 나머지 15개 | — | 당장은 `""` |

## 6. 가장 빠르고 편한 다음 단계 (우선순위)

> **원칙:** UI·registry·크롤러 패턴은 그대로 두고, **공통 레이어만** 확장

### Step 1 — CSV v3 호환 (1~2일, 효과 큼)

1. `backend/app/core/csv_schema.py`에 **V3_COLUMNS 26개** 추가
2. `csv_writer.py`에 `standard_to_v3()`, `save_v3_csv()` 추가
3. 크롤러는 기존 `empty_row()` 유지 → 저장 시 v3로 변환
4. UI 미리보기는 4컬럼 유지, **다운로드는 v3 파일** 옵션 추가 (또는 별도 API)

### Step 2 — 출력 경로·파일명 v3 규칙 (반나절)

```
data/output/
├── platform/
│   └── 29cm_20260604.csv
└── brand/
    ├── spa_global/zara_20260604.csv
    ├── spa_domestic/uniqlo_20260604.csv
    └── luxury/dior_20260604.csv
```

`crawler_service.py`에서 `track`(platform/brand) + `category` 메타를 `brands.json`에 추가.

### Step 3 — 증분 크롤링 (1일)

- `data/checkpoints/{id}_checkpoint.json` 저장
- 29cm: `sortType=NEW` 또는 신상 API
- 무신사: `?sortCode=NEW`
- 기준 URL/날짜 이후만 수집 + 기존 CSV merge

### Step 4 — 크롤러 추가 (사이트당 0.5~1일)

**API 우선 (빠름):** uniqlo, 29cm 패턴 재사용  
**Playwright 필수:** 무신사, W컨셉, ZARA, Dior

| 순서 | 대상 | 이유 |
|------|------|------|
| 1 | 무신사 | v3 플랫폼 트랙 1순위, 29cm과 함께 매일 |
| 2 | W컨셉 | 플랫폼 트랙 완성 |
| 3 | H&M, COS | ZARA/UNIQLO와 유사 SPA |
| 4 | Dior | 공식몰 차단 시 **무신사 럭셔리 / 29cm 명품 fallback** (v3 §8) |

### Step 5 — 스케줄러 (반나절)

Windows 작업 스케줄러 또는 `scripts/scheduler.py` + cron:

```
매일 09:00 → musinsa, 29cm(new-arrivals), wconcept
월~토 09:00 → brands.json의 track/day 필드 기준
```
