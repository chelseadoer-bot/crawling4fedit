# 패션 MD 크롤링 자동화 서비스 기획서

> 버전 v1.0 · 2026.06 · 대상: 내부 MD/패션기획팀

---

## 01. 서비스 개요

여러 패션 브랜드 사이트에서 상품 정보를 버튼 하나로 수집하고, **표준 CSV 파일**로 출력하는 내부 도구.

| 항목 | 내용 |
|------|------|
| 핵심 목표 | 브랜드별 크롤링 원클릭화 |
| 출력 형식 | 표준 CSV (통일 컬럼) |
| 주요 사용자 | MD / 패션기획팀 |
| 화면 구성 | 웹 기반 단일 페이지 앱 (SPA) |

### 배경 및 문제 정의

각 브랜드 사이트 구조가 달라, 담당자가 수작업으로 상품 정보를 취합하는 데 많은 시간이 소요됨.  
사이트마다 다른 방식으로 접근해야 하고, 결과물 형식도 달라 통합 분석이 어려움.

---

## 02. 핵심 기능 정의

### 기능 1 — 브랜드 관리 패널

- 등록된 브랜드 목록을 카드/리스트 형태로 표시
- 브랜드별 상태 확인 (활성/비활성, 마지막 수집일, 성공 여부)
- 새 브랜드 추가 · 수정 · 삭제

### 기능 2 — 크롤링 실행

- 개별 브랜드 단위 실행 또는 전체 일괄 실행
- 실행 중 진행 상태 표시 (진행바 또는 로그 스트림)
- 실패 시 에러 메시지와 재시도 버튼 제공

### 기능 3 — 결과 확인 및 CSV 다운로드

- 크롤링 완료 후 수집 건수, 실패 건수 요약 표시
- 수집 결과를 테이블 미리보기로 확인
- 단일 브랜드 CSV / 전체 통합 CSV 다운로드 버튼 제공

### 기능 4 — 브랜드 설정 (크롤링 규칙)

- 브랜드마다 크롤링 셀렉터·로직을 저장하는 설정 UI
- 기술자가 한 번 설정하면 MD팀은 버튼만 누르는 구조

## 03. 표준 CSV 컬럼 명세

> 인코딩: **UTF-8-BOM** (엑셀 호환)  
> 숫자 필드: 콤마·통화기호 제거 후 순수 숫자로 저장  
> 없는 필드: 빈 값으로 채움

| # | 컬럼명 (영문) | 한글명 | 예시 | 필수 여부 |
|---|--------------|--------|------|----------|
| 1 | brand | 브랜드명 | ZARA | ✅ 필수 |
| 2 | product_id | 상품코드 | ZR-2024-001 | ✅ 필수 |
| 3 | product_name | 상품명 | Linen Blend Blazer | ✅ 필수 |
| 4 | category_large | 대분류 | 아우터 | ✅ 필수 |
| 5 | category_small | 소분류 | 블레이저 | 선택 |
| 6 | price_original | 정가 | 89000 | ✅ 필수 |
| 7 | price_sale | 할인가 | 62300 | 선택 |
| 8 | discount_rate | 할인율(%) | 30 | 선택 |
| 9 | color | 색상 | 베이지, 블랙 | 선택 |
| 10 | sizes_available | 가용 사이즈 | XS,S,M,L,XL | 선택 |
| 11 | stock_status | 재고상태 | in_stock / out_of_stock / low | ✅ 필수 |
| 12 | product_url | 상품 URL | https://... | ✅ 필수 |
| 13 | image_url | 대표 이미지 URL | https://... | 선택 |
| 14 | crawled_at | 수집일시 | 2026-06-04 14:30:00 | ✅ 필수 |
| 15 | source_site | 수집 출처 도메인 | zara.com | ✅ 필수 |

## 04. 화면 구성 (페이지)

### 메인 대시보드

- **상단**: 전체 브랜드 수, 오늘 수집 건수, 실패 브랜드 수 요약 카드
- **중단**: 브랜드 카드 목록 (이름 / 마지막 수집일 / 상태 배지 / 실행 버튼)
- **하단**: 최근 실행 로그 테이블

### 브랜드 설정 페이지

- 브랜드명 / 사이트 URL / 크롤링 방식 선택 (정적 / 동적)
- 컬럼별 CSS 셀렉터 또는 XPath 입력 폼
- 페이지네이션 처리 방식 선택 (무한스크롤 / 다음 버튼 / URL 파라미터)
- 저장 및 테스트 실행 버튼

### 결과 뷰어 페이지

- 브랜드 선택 탭 → 수집 데이터 테이블 미리보기 (50건)
- 필터: 카테고리 / 할인 여부 / 재고 상태
- 단일 CSV 다운로드 / 전체 통합 CSV 다운로드

---

## 05. 크롤링 실행 플로우

```
실행 버튼 클릭
  → 브랜드 설정 로드
  → 사이트 접속 / 렌더링
  → 상품 목록 파싱
  → 컬럼 매핑
  → CSV 저장
  → 다운로드 제공
```

### 에러 처리 방침

- 타임아웃 (30초) 초과 시 자동 재시도 1회 → 실패 기록 후 다음 브랜드로 이동
- 상품 개별 파싱 실패 시 해당 행만 스킵, 나머지 계속 수집
- 실패 내역은 `error_log` 컬럼에 기록하여 별도 확인 가능

## 06. 기술 스택 방향 (권장)

### 백엔드

| 항목 | 선택 |
|------|------|
| 언어 | Python |
| 웹 프레임워크 | FastAPI |
| 동적 사이트 크롤링 | Playwright (Headless Chrome) |
| 정적 사이트 크롤링 | requests + BeautifulSoup4 |
| 스케줄러 (선택) | APScheduler |

### 프론트엔드

| 항목 | 선택 |
|------|------|
| 프레임워크 | React + Vite |
| 테이블 | TanStack Table |
| 상태관리 | Zustand 또는 Context API |
| UI 컴포넌트 | shadcn/ui |

### 데이터 저장

- SQLite (소규모) 또는 PostgreSQL (확장)
- 브랜드 설정 / 실행 이력 / 수집 결과 저장
- 빠른 시작 시: JSON config 파일 + CSV 누적 방식도 가능

### 배포

- Docker 컨테이너
- 내부망 또는 팀 서버 배포 (외부 공개 불필요)

## 08. 고려사항 및 제약

### 법적·윤리적 고려

- `robots.txt` 준수 필요
- 과도한 요청으로 서버 부하 금지 (요청 간 딜레이 설정 필수)
- 수집 데이터는 내부 기획 목적으로만 사용

### 사이트 구조 변경 대응

- 브랜드 사이트 리뉴얼 시 셀렉터가 깨질 수 있음
- 설정 페이지에서 담당자가 직접 셀렉터를 수정할 수 있는 구조로 구현
- 실패 알림 이메일/슬랙 연동 고려

### 차단 대응

- 일부 브랜드 사이트는 크롤링 차단 (Cloudflare 등)
- User-Agent 설정, 요청 딜레이 조정으로 1차 대응
- 필요 시 수동 수집 병행 방안 안내 필요
